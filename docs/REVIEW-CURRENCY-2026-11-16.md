### ffmpeg from mise (2026-11-17)

Maintainer question: "Can we cache the packages in CI?" `tests/audio-assets.spec.ts` needs ffmpeg
and ffprobe and fails rather than skips under `CI`. The `verify` job installed them with
`apt-get` on every run; on 2026-11-17 a slow Ubuntu mirror made that step take 16 minutes and
the job hit its 20-minute limit. PR #247 bounds and retries that apt step as a safety net.

Choice: **`conda:ffmpeg` 9.0.2 through mise**, the first backend the mise registry lists for
`ffmpeg`. It joins the pinned toolchain, so `jdx/mise-action` (already in the job) installs it
and caches it with the rest: the action's cache key hashes `mise.toml` and `mise.lock`
(`src/config-hash.ts` at the pinned `236a21c3`), and its cached path is the whole mise data
directory, `installs/conda-ffmpeg/` included. With a lockfile present the action runs
`mise install --locked`, which installs only what the lockfile names.

| Question | Answer |
|---|---|
| Version | 9.0.2, the newest upstream release (`git ls-remote` of git.ffmpeg.org: newest tag `n9.0.2`; no 9.1). `mise ls-remote conda:ffmpeg` lists 9.0.2 as newest |
| Build | `linux-64/ffmpeg-9.0.2-gpl_hac98dcb_908.conda`, SHA-256 `73ed9368...9a2102`, identical to the `sha256` the anaconda.org API gives for that file |
| Licence | GPL-2.0-or-later (configured `--enable-gpl --enable-version3`). conda-forge also publishes LGPL builds, but mise's conda backend picks the build and exposes no build-string pin. Ubuntu's apt `ffmpeg` is also a GPL build, so nothing changes. It is a development and CI tool: nothing from it is bundled into the app, the web export or the SBOM |
| Pinning | `mise.lock` records the ffmpeg package and all 137 linux-x64 conda dependencies, each by URL and SHA-256 (`[conda-packages.linux-x64.*]`) |
| ffprobe | in the same package; `mise which ffprobe` resolves it |
| Size | 138 package files, 163.7 MB downloaded (sum of `Content-Length`), 665 MB installed. Most of the bulk is libraries the audio checks do not use (OpenVINO 137 MB, Mesa DRI drivers 46 MB, x265, ICU); conda-forge publishes no slimmer ffmpeg |
| Measurement | `CI=1 pnpm exec vitest run tests/audio-assets.spec.ts` passes 10 of 10 with 9.0.2. The ebur128 integrated loudness and true peak of all 34 committed files print byte-identical under apt ffmpeg 8.0.1 and conda ffmpeg 9.0.2, so the figures in docs/SOUNDTRACK.md and docs/VOICE-CLIPS.md still hold |

CI now checks that `ffmpeg` and `ffprobe` on `PATH` are the ones `mise which` names, so a copy on
the runner image cannot stand in for the pin. The apt step is gone; no apt install of ffmpeg
remains anywhere in CI. Locally, `mise install` (run by `scripts/bootstrap-ubuntu.sh`) installs
it too.

Rejected alternatives: `actions/cache` of the apt `.deb` archives still needs `apt-get update`
(the step that met the slow mirror) or a hand-run `dpkg -i` of a dependency set the runner
image can change under it, and leaves the version to the Ubuntu archive. A static build
(johnvansickle.com, BtbN/FFmpeg-Builds) would be a second pinning mechanism beside mise and its
lockfile, and BtbN keeps only the last 14 daily builds and each month's last build for two years
(its README), so a pinned URL has a shelf life. The registry's other backend,
`asdf:mise-plugins/mise-ffmpeg`, downloads the source tarball and runs `./configure && make` on
every cold install.

  2.2.0). Lifts when an Expo SDK or SDK patch changes the expected version; `npx expo install
  --check` is the test. async-storage 3 is also a major with its own API changes.
- **H3. JDK 25.** Gradle 9.4.1 can run on Java 25 according to Gradle's compatibility table
  (9.1.0 and later), but React Native 0.88's environment guide recommends JDK 17 and warns
  that higher versions may cause problems; 21 is the version the recorded release builds
  used. Changing the JDK is only testable by a native rebuild and a device or emulator run.
  Lifts when React Native documents a newer JDK, or after a deliberate native qualification.
